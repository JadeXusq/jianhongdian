## 二、关键发现

### 🟡 改进建议（强烈建议）

#### [16] 旋转模式下手牌触摸目标偏窄

- **现象**：竖屏软件旋转后，手牌变为屏幕左侧的垂直堆叠。在模拟视口（651×733）下，手牌区域宽约 30-80px。虽然代码有 `+12px` 命中外扩（`table.ts` 命中测试），但在真机手指触摸（指腹约 44×44pt）下仍可能偏窄。
- **影响**：玩家在竖屏旋转模式下选牌时，可能误触相邻牌或完全 miss。特别是手牌较多（12 张）时，牌间距更小。
- **根因**：旋转后逻辑宽度 1040px 映射到物理 733px（scale ≈ 0.7），手牌宽度从逻辑 96px 缩小到物理约 68px，再扣除重叠部分，实际可触宽度更小。
- **建议**：考虑在 `pointer: coarse` + `shouldRotate()` 为 true 时，增大手牌命中外扩至 +20px 或更多；或减小手牌重叠比例。

#### [17] 得分条展开面板在旋转模式下遮挡桌面

- **现象**：点击得分条展开"已吃牌"面板后，面板出现在屏幕中央，遮挡了桌面牌区域。在移动端有限的屏幕空间下，这一遮挡更为明显，影响玩家查看可配对的桌面牌。
- **影响**：玩家展开得分面板后无法同时查看桌面牌，需要先关闭面板才能继续游戏。
- **建议**：在移动端（`pointer: coarse`）模式下，将展开面板位置调整到底部或侧边，避免覆盖桌面核心区域；或减小面板尺寸。

### 🟢 优化建议（锦上添花）

#### [18] 未观察到 MATCH 动画及"点击跳过"提示在旋转模式下的表现

- **现象**：本次体验中未触发 MATCH 动画（可能因为坐标命中精度不足，未能精确选择可配对的牌）。
- **影响**：无法确认 MATCH 粒子光效和"点击任意处跳过"胶囊提示在旋转模式下是否正确显示。
- **建议**：后续补充测试 MATCH 动画在旋转模式下的渲染效果。

#### [19] 未观察到结算面板在旋转模式下的表现

- **现象**：本次体验未能完成完整一局（手牌剩余较多时评审时长已达上限）。
- **影响**：无法确认结算界面（轮次圆点、排名列表、继续/退出按钮）在旋转模式下的布局适配。
- **建议**：后续补充测试结算面板在旋转模式下的显示效果。

## 三、亮点

1. **软件旋转方案成熟**：不依赖 `screen.orientation.lock()`（iOS 不支持），改用 CSS `transform` + Canvas 坐标逆变换，兼容性优秀。`pointer-events: none` 确保旋转的 UI 层不拦截 Canvas 触摸事件。

2. **离线模式无缝衔接**：新增 `localPlay.ts` 完全脱离服务器运行，AI 逻辑复用 `shared/` 规则引擎，数据结构与联机模式对齐，`TableView` 可复用渲染逻辑。玩家无需服务器即可体验完整游戏。

3. **移动端布局自适应**：`#ui.rot .lobby-panel` 双列网格布局、表情按钮竖排靠右、安全区 `env(safe-area-inset-*)` 适配刘海屏，均体现了对移动端的深度适配。

4. **历史修复项在移动端全部通过**：弃牌确认 toast（#4）、得分条展开（#8）、分值速查（#13）、∨/∧ 收起暗示（#15）在旋转模式下均正常工作，无回归。

## 四、优先级排序建议

1. **[16] 旋转模式手牌触摸目标偏窄** — 理由：直接影响竖屏玩家的核心操作体验，修复成本低（调大命中外扩即可）
2. **[17] 得分条展开面板遮挡桌面** — 理由：影响游戏中的信息获取，移动端屏幕空间有限
3. **[18] MATCH 动画旋转模式验证** — 理由：需补充测试，可能发现问题
4. **[19] 结算面板旋转模式验证** — 理由：需补充测试，确保完整流程无障碍
