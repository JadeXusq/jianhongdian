## 关键发现

### 🔴 严重问题（必须修复）

#### 20 动画主循环停摆，「出牌结算中…」长时间无法操作

- **现象**：对局中 `view.animClock` 完全冻结，动画队列积压（曾见 `stepsLen=20`），回合提示长期停在「出牌结算中…」。页面级 `requestAnimationFrame` 仍可用，但游戏 `frame()` 不再驱动 `view.render`；手动 `view.render(dt)` 可消化队列。
- **复现**：人机 4 人局，弃牌确认后进入多段吃牌/翻牌动画堆积时出现（本环境 IDE 浏览器亦有 RAF 节流，可能放大问题）。
- **影响**：玩家无法出牌，体验直接中断；若真机也存在主循环被异常打断的路径，属于阻塞级。
- **建议**：
  1. `frame()` 用 `try/finally` 保证末尾始终 `requestAnimationFrame(frame)`，避免单次异常杀死整局渲染；
  2. 开发态对 `frame` 内异常打点；
  3. 动画队列设上限或合并，避免 AI 连出时 steps 暴涨。
- **依据截图**：`screenshots/stuck-settling.png`

#### 21 最终结算页「结算本场」因 `.hidden` 未生效仍可见可点

- **现象**：`#btn-result-settle` 已加 class `hidden`，但计算样式仍为 `display:block`，最终结算（「最终结算（1 轮）」）上仍露出「结算本场」。
- **复现**：菜单 → 结算对局 → 确定后查看结果面板。
- **影响**：终局后仍出现「再结算」入口，语义混乱，易误触。
- **建议**：补全局 `.hidden { display: none !important; }` 或至少 `.btn.hidden, .panel-x.hidden { display: none; }`；并审计其它仅靠 `classList.add("hidden")` 的按钮（如菜单结算在非房主场景）。
- **代码**：`client/src/styles.css` 仅有 `.screen.hidden` / `.chat-*.hidden` 等特例，无通用 `.btn.hidden`。
- **依据截图**：`screenshots/final-result.png`

### 🟡 改进建议（强烈建议）

#### 22 积分面板文案「已完成 N 轮」把进行中轮次算成已完成

- **现状**：对局中 `state.round === 1` 时，积分副标题显示「已完成 1 轮 · 累计净分」。
- **问题**：第 1 轮尚未结束就被说成「已完成」，与累计净分全 0 并存，新手会以为结算逻辑坏了。
- **建议**：改为 `已完成 ${Math.max(0, state.round - 1)} 轮`，或「第 N 轮进行中 · 累计净分」。
- **代码**：`client/src/main.ts` `renderScores()` 约 380–382 行。
- **依据截图**：`screenshots/scores-panel.png`

#### 23 桌面边角残留裁切牌面（4♠ / 7♠）

- **现状**：多段对局中，屏幕角落反复出现半张牌（先 4♠ 后 7♠），不在正常桌面牌槽内。
- **问题**：像「漏画/卡动画」的脏画，削弱精致感；与动画堆积同时出现时更明显。
- **建议**：排查 `lingerTable` / 飞牌 `flies` 在步骤被跳过或主循环停摆后的清理；渲染时裁剪到桌面矩形内。
- **依据截图**：`screenshots/chat-and-edge-card.png`

### 🟢 优化建议（锦上添花）

#### 24 聊天面板在旋转竖屏下遮挡手牌区偏多

- **理由**：移动端横屏逻辑分辨率本就紧，社交与出牌视线争抢。

- **想法**：弃牌 toast 在后续多轮操作后仍可能挂着旧文案；应在回合切换 / 出牌成功时强制清空。
