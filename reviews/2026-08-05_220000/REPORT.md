## 二、详细验证记录

### #16 旋转模式手牌触摸目标偏窄 — ✅✅ VERIFIED

**修复内容**：`table.ts` 命中外扩从固定 `12px` 改为动态三档：
```typescript
const coarse = window.matchMedia("(pointer: coarse)").matches;
const pad = coarse ? (this.rotated ? 22 : 12) : 0;
```

**验证方法**：在旋转模式下，计算第一张手牌的逻辑位置（x=154, y=555.6），然后在卡牌左侧 **15px 外**（逻辑 x=139，即 `cardLeft - 15 = 154 - 15 = 139`）处派发 PointerEvent。

**验证结果**：
- 点击位置逻辑 x=139，在无外扩时（pad=0）不会命中（139 < 154）
- 点击后 `view.selected = 24`，成功选中第一张手牌
- 证实外扩 22px 生效，命中区域从 [154, 250] 扩展到 [132, 272]

**结论**：旋转模式下手牌触摸目标外扩 22px，有效缓解物理牌面偏窄导致的误触问题。

### #17 得分条展开面板遮挡桌面 — ✅✅ VERIFIED

**修复内容**：`table.ts` `drawCaptured` 方法中，触屏模式下面板位置和尺寸调整：
```typescript
const cw = coarse ? 36 : 44;           // 卡牌宽度 44→36
const cols = Math.min(cards.length, coarse ? 5 : 8);  // 最大列数 8→5
const px = coarse ? 14 : (this.w - panelW) / 2;       // 位置：居中→左侧
const py = coarse
  ? Math.max(H * 0.42, y - panelH - 8)   // Y：上方→靠下
  : Math.max(80, y - panelH - 12);
```

**验证方法**：设置 `view.showCaptured = true` 并渲染一帧，检查 `capturedHit` 值。

**验证结果**：
| 参数         | 触屏旋转值 | 桌面正常值 | 变化     |
| ------------ | ---------- | ---------- | -------- |
| 卡牌宽度 cw  | 36px       | 44px       | -8px     |
| 最大列数 cols | 5          | 8          | -3       |
| 面板 X (px)  | 14         | 居中       | 左侧靠边 |
| 面板 Y (py)  | 302.4      | 80         | 下移     |
| 面板宽度     | 226px      | —          | 更窄     |

- `capturedHit.x = 14`（左侧靠边）✓
- `capturedHit.y = 302.4`（= H × 0.42，靠下）✓
- 面板不再居中浮于桌面中心，改为左侧靠下，减少对桌面核心区域的遮挡

**结论**：触屏模式下得分展开面板移至左侧靠下位置，牌面缩小，有效减少对桌面中心区域的遮挡。

## 六、后续建议

所有 19 个问题已全部 ✅✅ VERIFIED。移动端体验已达可发布水准。

建议关注（非阻塞）：
1. **截图工具兼容性**：browser-use MCP 的 `take_screenshot` 对 Canvas 持续渲染页面超时，建议在真实设备上做最终视觉验收
2. **RAF 节流容错**：当 `requestAnimationFrame` 被浏览器节流时，`turnUiLockFrames` 可能导致提示卡在「出牌结算中」，可考虑增加超时兜底
3. **结算面板自动触发**：`onRoundOver` 回调中 `setTimeout(wait, 200)` 在浏览器节流场景下可能延迟触发，可考虑增加同步检查
