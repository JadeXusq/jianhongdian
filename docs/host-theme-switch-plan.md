# 房主切主题：评估与实现方案

> 状态：一期已按拍板实现（对局中可切 / 2 套 / 双端 / 第二套动漫风）  
> 日期：2026-08-09  
> 范围：Web（`client/`）+ Cocos（`cocos/`）+ 服务端房间状态（`server/`）

---

## 1. 背景与目标

### 现状

主题目前是写死的：

| 端 | 位置 | 内容 |
|----|------|------|
| Web 牌桌 | `client/src/theme.ts` | canvas 配色 `C` |
| Web UI | `client/src/styles.css` | CSS 变量 `--gold` / `--felt` 等 |
| Cocos | `cocos/assets/scripts/Theme.ts` | `Color` 常量 |
| 房间状态 | `server/src/state.ts` | **无** theme 字段 |

房主权限已有（如结算本场），切主题可复用同一套 host 校验。

### 目标（建议）

- **房主**可在房间内切换主题
- **同房间全员**看到同一主题（含观战）
- 先做 **2～3 套配色主题**（桌布/描边/强调色/面板），不先上整套牌面贴图皮肤
- Web 与 Cocos **行为对齐**

## 2. 方案选项

| 方案 | 含义 | 工作量 | 建议 |
|------|------|--------|------|
| A. 仅本机换皮 | 每人本地选主题，不同步 | 低 | 与「房主」弱相关，不推荐作主方案 |
| **B. 房间同步主题** | 房主选，`themeId` 进房间状态，全员应用 | 中 | **推荐** |
| C. 完整皮肤包 | 配色 + 牌背/桌布图 + 可选音效 | 高 | 二期再做 |

下文按 **方案 B** 展开。

---

## 3. 工作量与复杂度

### 总估时

| 范围 | 预估 |
|------|------|
| Web + 服务端 + Cocos，2～3 套配色，房间同步 | **约 3～5 人日** |
| 仅 Web + 服务端，Cocos 暂缓 | 约 1.5～2.5 人日 |
| 再加牌背/桌布贴图资源 | 再加 2～4 人日 |

### 复杂度：**中等、可控**

不是架构重做，核心是：

1. 色板数据化（从常量 → 可切换字典）
2. 房间状态同步 `themeId`
3. 双端在状态变化时应用主题并重绘

### 主要风险点

1. **Canvas 与 CSS 两套样式**：只改 CSS 变量，牌桌 canvas 仍是旧色 → 必须同时切 `theme.ts` / 绘制色
2. **对局中途切换**：需立即重绘桌面，不能只在进房时读一次
3. **Web ↔ Cocos 同步**：按仓库规则两端都要落地
4. **权限与时机**：仅房主可改；是否允许对局中切换需产品定夺

## 4. 推荐产品规则（待确认）

| 项 | 建议默认 |
|----|----------|
| 谁能改 | 仅房主 |
| 何时能改 | **等待房（WAITING）可改**；对局中（PLAYING）可选：禁止 / 允许即时生效 |
| 人机练习 | 本机玩家等同房主，可本地切换（不必上服务器） |
| 重连 / 观战 | 跟房间当前 `themeId` |
| 主题数量（一期） | 2 套：现版「青绿金」+ 1 套备选（如墨红 / 夜蓝，具体色值另定） |
| 持久化 | 一期可不做账号级记忆；可选 `localStorage` 记住房主上次选择，仅用于建房默认值 |

请确认：**对局中是否允许切主题**。影响实现分支与测试量。

## 5. 技术方案

### 5.1 主题数据

新增共享色板定义（建议放 `shared/` 或双端各一份同源结构），例如：

```ts
type ThemeId = "jade" | "ink"; // 一期 2 套

interface ThemeColors {
  id: ThemeId;
  name: string; // 展示名，如「青绿金」
  // canvas / UI 共用语义色
  feltInner: string;
  feltOuter: string;
  gold: string;
  goldDim: string;
  seal: string;
  cream: string;
  ink: string;
  cardFace: string;
  cardBack: string;
  // CSS 可再映射一层
}
```

- Web：`applyTheme(id)`  
  - 写 `document.documentElement` 的 CSS 变量  
  - 更新 canvas 用的运行时 `C`（或改为 `getTheme().xxx`）
- Cocos：`applyTheme(id)` 更新 `Color` 并触发相关节点重绘

### 5.2 服务端 / 协议

在 `RoomState` 增加：

```ts
themeId: string; // 默认 "jade"
```

消息：

- 客户端 → 服务端：`setTheme` `{ themeId }`
- 校验：发送者必须是房主；`themeId` 在白名单内
- 非法：忽略或 `error` 提示

状态变更走 Colyseus schema 同步，客户端 `onState` 里应用主题即可（不必单独 broadcast，除非想做「切换提示」toast）。

### 5.3 客户端入口（UI）

建议放在 **房间页（WAITING）**，仅房主可见：

- 文案示例：「桌面主题」+ 分段按钮 / 下拉（2～3 项）
- 非房主：只读展示当前主题名，或不展示切换器
- 人机：大厅或开局前提供同样入口

对局中菜单是否放入口：取决于「对局中是否允许切换」。

### 5.4 应用时机

| 时机 | 行为 |
|------|------|
| 加入房间 / 重连 | 读 `state.themeId` → `applyTheme` |
| 房主切换 | 发 `setTheme` → 全员 state 更新 → `applyTheme` + 若在牌桌则重绘 |
| 人机本地 | 直接 `applyTheme`，并写入本地会话状态（若有） |

### 5.5 文件改动预估（方案 B）

| 区域 | 可能涉及 |
|------|----------|
| `shared/` | 主题 id 白名单、可选色板常量 |
| `server/src/state.ts` | `themeId` 字段 |
| `server/src/GameRoom.ts` | `setTheme` 处理、host 校验 |
| `client/src/theme.ts` + `styles.css` | 多套色板、CSS 变量、apply |
| `client/src/main.ts` / 房间 UI | 房主切换入口 |
| `client/src/net.ts` | `setTheme` 发送 |
| `client/src/table.ts` | 使用运行时主题色（避免闭包旧色） |
| `cocos/.../Theme.ts`、`LobbyUI.ts`、`GameEntry.ts`、`Net.ts` | 对齐 |
| `client/src/localPlay.ts` | 人机侧 theme 字段（可选） |

## 6. 分期建议

### 一期（MVP）— 建议先做

- 2 套配色
- 房间同步 + 房主切换（WAITING）
- Web + Cocos
- 人机可切
- 对局中：**禁止切换**（实现简单、无中途重绘争议）

### 二期

- 对局中可切换并即时重绘
- 第 3 套主题
- 房主建房默认主题记忆（localStorage / 账号）

### 三期（完整皮肤）

- 牌背 / 桌布图集
- 主题预览缩略图
- 可选主题音效

---

## 7. 验收清单（一期）

- [ ] 房主在等待房切换主题，自己与其他成员、观战方 UI/桌面一致
- [ ] 非房主无法切换（按钮隐藏或点了提示无权限）
- [ ] 重连后主题与房间一致
- [ ] 人机练习可切换且立即生效
- [ ] Web / Cocos 两套主题观感对齐（不必像素级一致，色语义一致）
- [ ] 切主题不导致布局错乱、牌桌缩小等回归
